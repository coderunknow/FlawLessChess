### Naming (conflict noted)

The approved decision names the Rust package `Flawless-Chess-Engine`. The repository's package is
`flawless` (`Cargo.toml`, `Cargo.lock`, `use flawless::…`, binary `flawless`). Renaming would break
imports, the binary name used by CI and tests, and the release artifact name. The package was
**not** renamed; the `Flawless-Chess-Engine` name appears only as the GitHub repository's former
name in `docs/adr/0002-flawless-identity.md` and `docs/ENVIRONMENT.md`. Decision needed: confirm
`flawless` as the package name, or approve a rename as a separate change.

## Performance (2-vCPU Linux sandbox, release build, interactive measurement)

- Bench (depth 10, 12 positions): 2,530,885 nodes; 441,563–443,569 nps (two runs). Signature `141943aa23b3fc68`.
- `go movetime 3000`, startpos, hash 16/64/256 MB: wall 3001–3003 ms, CPU 3.00 s (one core, 100%).
  Peak RSS 21.2 / 69.0 / 198.5 MiB; idle RSS about 5 MiB. Peak tracks the hash size (+ overhead).
- Nodes in 3 s: about 1.15 M (depth 13) for startpos.
- Startup to `readyok`: well under 0.1 s.
- Not measured: Windows NPS, RSS and CPU; multi-core (engine is single-threaded by design, `Threads` max 1).

## Movetime change (search timing)

- Cause: `src/search.rs` iterative deepening stopped when `now + 3 × last_iteration > soft_budget`.
  With `go movetime N`, the soft budget equals N, so searches stopped at 39–100% of N.
- Change: `SearchLimits.fixed_time` (true only for `go movetime`) disables the growth-prediction stop.
  The hard deadline (= N) still ends the search; clock-based searches are unchanged.
- Evidence: before/after measurements and the `movetime_smoke` tests (the test fails on the old rule).
- Effect on rating evidence: `benches/` results collected with the old movetime behaviour were run
  under a different time policy. They are not comparable to new movetime results. Clock-based (`wtime`)
  evidence is unaffected by this change.
